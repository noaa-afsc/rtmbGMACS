## User

how do I use a GitHub PAT with pkgdown?

## Assistant

For this project’s GitHub Actions workflow, a personal access token is **not normally needed**. [`.github/workflows/pkgdown.yaml`](.github/workflows/pkgdown.yaml) uses the automatically generated `GITHUB_TOKEN` with `contents: write` permission. This is safer than maintaining a PAT.

For local pkgdown deployment, create a fine-grained PAT with repository **Contents: Read and write** access, authorize it for NOAA’s organization/SSO if required, then store it through R’s credential manager:

`usethis::create_github_token()` opens GitHub’s token-creation page.

`gitcreds::gitcreds_set()` securely prompts for and stores the token. Do not place it in `_pkgdown.yml`, source code, or a committed `.Renviron` file.

Afterward, local deployment can use `pkgdown::deploy_to_branch()`. The token is retrieved from the system credential store.

If a custom PAT is required in GitHub Actions, create a repository secret under **Settings → Secrets and variables → Actions**, name it something such as `PKGDOWN_PAT`, and change the workflow environment mapping to `GITHUB_PAT: ${{ secrets.PKGDOWN_PAT }}`.
